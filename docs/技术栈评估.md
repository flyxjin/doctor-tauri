# 技术栈评估（2026-09）

> 目的：对照 2026 年当前技术现状，评估本项目技术栈的升级空间。
> 结论先行：**骨架（Tauri 2.x + rusqlite + TanStack Query 5）无需更换**，
> 前端构建链与运行时有三个批次值得升级，均已给出风险与路径。

## 一、现状盘点（package.json 实际锁定版本 vs 当前生态）

| 层 | 项目当前 | 生态当前（2026-09） | 判定 |
|----|---------|--------------------|------|
| 桌面框架 | Tauri 2.x（Cargo.toml 2.11.5 系） | Tauri 2.11.5（2.x 即当前稳定主推线，3 尚未 stable） | ✅ 已是最新代 |
| UI | React 18.3 | React 19.3（2026-09） | ⬆️ 建议升 |
| 组件库 | antd 5.20 | antd 6.0（2025-11 发布，面向 React 19） | ⬆️ 与 React 19 绑定升 |
| 构建 | Vite 5.4 | Vite 8.x stable（Rolldown 内核）；7.3 维护线 | ⬆️ 建议升 |
| 语言 | TypeScript 5.5 | TS 6.0（2026-03，桥接版）；TS 7（Go 原生编译器）已宣布 | ⬆️ 升 6.0，观望 7 |
| 测试 | Vitest 2.1 | Vitest 4.x（2025-10，需 Node 20.19+） | ⬆️ 与 Vite 升级联动 |
| 服务端状态 | TanStack Query 5.51 | React 侧 v5 仍是最新稳定（v6 仅 Svelte stable） | ✅ 不动 |
| Lint | ESLint 9 flat + typescript-eslint 8 | 主流形态 | ✅ 跟随小版本 |
| 存储 | rusqlite（bundled SQLite） | 稳定 | ✅ 不动 |

## 二、建议升级批次

### 批次 1（低风险，一次 PR 完成）：构建链
- **Vite 5 → 7.3**：构建/热更新速度显著提升；要求 Node 20.19+（CI 与本机均满足）。
  注意：`manualChunks` 配置在升级后回归验证分包；`@vitejs/plugin-react` 同步升。
- **Vitest 2 → 4**：与 Vite 版本联动，本项目测试均为纯 Node 环境单测，破坏面小。
- **TypeScript 5.5 → 6.0**：桥接版本，默认更严格——正好当一次全量类型体检
  （项目已是 `strict: true`，预期改动极小）。
- 护航：`npm run typecheck && npm test && npm run build` + 手动冒烟。
- 顺带：在 package.json 增加 `engines.node = ">=20.19"` 固化运行时下限。

### 批次 2（中风险，独立 PR）：React 19
- 18 → 19.3：受益于 React Compiler 自动 memo 化（开处方页大列表渲染可受益）、
  为 antd 6 铺路。
- 若暂不升 antd 6，需引入 `@ant-design/v5-patch-for-react-19` 兼容包。
- 回归重点：全部页面冒烟（antd 5 在 React 19 下主要是 findDOMNode 类告警）。

### 批次 3（计划性）：antd 5 → 6
- 官方定性为"技术性升级、组件 API 大体兼容"，有官方 V5→V6 迁移指南；
- 与批次 2 可合并为一个 PR 一次回归（UI 细节走查全部页面，浅色/深色两主题）。

### 长期观察（不执行）
- **Tauri 3**：未 stable，2.x 是官方当前主推线，关注即可；
- **TypeScript 7**（Go 原生编译器，~10 倍速度）：等 typescript-eslint 等生态跟进后再切；
- **TanStack Query v6 (React)**：尚未 stable。

## 三、明确不建议动的

- **不引入 SSR/元框架**（Next.js 等）：桌面应用无 SEO/首屏诉求，纯增复杂度；
- **不换状态管理**：TanStack Query 5 即最新；本地 UI 状态用 useState/Context 足够；
- **不换 `rusqlite` 直用为 `tauri-plugin-sql`**：现有方案类型安全、迁移自由、
  可控的 WAL/PRAGMA 调优是插件的通用封装给不了的；
- **不重写自研 updater 为 tauri-plugin-updater**：现方案已具备 SHA256 + 下载源白名单 +
  路径校验；若未来要 minisign 级签名再评估官方插件（其需要 ed25519 密钥体系，
  发布流程要配套改造）。

## 四、依赖卫生

- `read-excel-file` 走 `browser` 子路径动态导入，按需加载 ✓；
- 建议 CI 增加一步 `npm audit --omit=dev`（仅生产依赖，告警不阻断），每月人工复核；
- Cargo 侧 `cargo deny`/`cargo audit` 可选接入 CI。
