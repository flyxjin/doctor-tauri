## P0 — 商用门槛（必须）

### 1. 代码签名证书

- **Issue**: [IK3Y7P](https://gitee.com/flyxjin/doctor/issues/IK3Y7P)
- **目标**: 消除 Windows SmartScreen「未知发布者」警告
- **方案**:
  - 购买 OV 证书（~¥1500/年）或 EV 证书（~¥3500/年）
  - Tauri 配置 `signtool` 钩子（`tauri.conf.json` → `bundle.windows.certificateThumbprint`）
  - CI release.yml 集成签名步骤
- **验收**: 安装时无 SmartScreen 警告，文件属性显示发布者

### 2. PDF 处方导出

- **Issue**: Gitee 已有
- **目标**: 处方单可导出为 PDF 文件落盘
- **方案**:
  - 后端：`printpdf` crate 或 `wkhtmltopdf` 绑定
  - 前端：`tauri-plugin-printer` 或浏览器打印另存为 PDF
- **验收**: 处方详情页「导出 PDF」按钮，生成带药店名称的 PDF 文件

### 3. GitHub Actions Release 工作流

- **目标**: tag 触发自动构建 NSIS + 上传 Gitee Release
- **方案**: 参考 `python_app/.github/workflows/release.yml`，新建 `tauri_app/.github/workflows/release.yml`
- **验收**: 推送 `v*` tag 自动触发构建，CI 产出 NSIS 安装包并创建 Release

## P1 — 体验增强（推荐）

### 4. 全局快捷键系统 ✅（已完成）

- **目标**: 支持常用快捷键（Ctrl+S 保存 / Ctrl+1~9 切换页面 / F1 帮助）
- **实现**: React window keydown 监听（MainLayout + Prescription 页），无需额外插件
- **验收**: F1 显示快捷键说明 Modal，Ctrl+1~9 切页、Ctrl+S 保存处方均可用

### 5. Excel (.xlsx) 批量导入

- **目标**: 除 CSV 外支持 Excel 格式批量导入
- **方案**: 前端 `xlsx` 库解析，或后端 `calamine` crate
- **验收**: 批量导入页支持选择 .xlsx 文件，自动转换为统一数据结构

### 6. 帮助 / 快捷键说明对话框 ✅（已完成）

- **目标**: 应用内随时查看快捷键清单
- **实现**: Ant Design Modal + 快捷键表，F1 全局触发
- **验收**: F1 弹出快捷键说明

### 7. 集成测试 / E2E 测试

- **目标**: 覆盖核心业务流（开方→扣库存→删除→回扣）
- **方案**: Playwright + Tauri WebDriver
- **验收**: CI 跑 E2E 测试通过

## P2 — 锦上添花（可选）

### 8. 更多方剂模板 ✅（已完成）

- **目标**: 扩充至 50+ 张方剂模板
- **实现**: `src/data/prescription_templates.json` 扩充至 53 张，新增 21 张经典方剂，全部药材经脚本校验与 400 味数据库匹配
- **验收**: 模板选择对话框按分类展示，支持搜索

### 9. 数据库迁移工具

- **目标**: 支持数据库 schema 版本管理与回滚
- **方案**: 引入 `refinery` crate 或保持现有 `schema_migrations` 表 + 增加回滚支持
- **验收**: 可查看迁移历史，可回滚最近一次迁移

### 10. 主题切换 ✅（已完成）

- **目标**: 支持浅色/深色主题切换
- **实现**: Ant Design ConfigProvider + `theme.darkAlgorithm`，配合 CSS 变量覆盖，localStorage 持久化
- **验收**: 顶栏灯泡按钮切换主题，重启后保持

### 11. 多语言支持

- **目标**: 支持简体中文 / 繁体中文 / 英文
- **方案**: `react-i18next` + 语言资源文件
- **验收**: 设置页可切换语言，所有文案翻译

### 12. 数据导入导出向导 ✅（已完成，精简版）

- **目标**: 统一的数据导入导出界面，支持药材 / 处方 / 患者多类型
- **实现**: 设置页「数据导入导出」卡片：前往批量导入 / 下载导入模板 / 导出全量药材 CSV；处方与患者导出保留在各自页面
- **验收**: 设置页有「数据迁移」入口，打通模板下载→批量导入→全量导出闭环

## 维护策略

### Tauri 版（主推）

- **接收**: 新功能、Bug 修复、安全补丁、性能优化
- **发布节奏**: 每月 1-2 个 minor 版本，关键 Bug 随时 patch

### Python 版（Legacy）

- **仅接收**: 重大 Bug 修复、安全漏洞补丁
- **不接收**: 新功能、性能优化、UI 改进
- **最终状态**: 维护至 2027-07-28（1 年），之后视用户反馈决定是否归档

### 数据互通

两版数据库 schema 保持对齐，用户可在两版之间迁移数据：
- Tauri 版 Settings → 创建备份
- Python 版 Settings → 还原备份（反之亦然）
- 备份前需关闭另一版本，避免数据库锁

## 决策记录

### 为什么选择 Tauri 版作为主推？

1. **功能更完整**: 400 味药材 vs 300 味、32 张模板 vs 22 张、FEFO 出库、过敏检测、SVG 图表
2. **安全更深入**: CSP 策略、SQL 全参数化、路径遍历防护、金额服务端重算、CRUD 全事务原子化
3. **性能更优**: Rust 原生编译启动秒开、WAL 模式、N+1 查询消除、Vite 五分包
4. **工程化更成熟**: 版本号 SSOT 同步脚本、39 个 IPC 命令、10 张业务表、16 个版本的 CHANGELOG
5. **打包更简洁**: 单文件即开即用，无需首次联网下载 Python 环境

### 为什么不直接废弃 Python 版？

1. **学习价值**: PySide6 + SQLAlchemy 2.0 ORM + PyAppify 是完整的 Python 桌面开发教学案例
2. **软著保护**: 两版代码完全不同，分别申请两个软著可最大化知识产权保护范围
3. **历史兼容**: 已有 Python 版用户可继续使用，数据可迁移到 Tauri 版
4. **维护成本低**: 仅修关键 Bug，不投入新功能开发，维护负担可控
