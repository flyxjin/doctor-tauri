## 1. 环境准备

### 1.1 必需软件

| 软件 | 最低版本 | 说明 |
|------|----------|------|
| Node.js | 18.0+ | 前端构建工具 |
| Rust | 1.75+ | 后端编译 |
| npm/pnpm | npm 9+ | 包管理 |

### 1.2 安装 Rust

**Windows（推荐 GNU 工具链）：**

```powershell
# 方式 1：通过 rustup 安装
winget install Rustlang.Rustup

# 方式 2：手动下载
# 访问 https://win.rustup.rs/x86_64 下载并运行

# 安装 GNU 工具链（避免 MSVC link.exe 依赖问题）
rustup toolchain install stable-gnu
rustup default stable-gnu
```

**验证安装：**

```powershell
rustc --version   # 应输出 rustc 1.75+
cargo --version   # 应输出 cargo 1.75+
```

### 1.3 安装 Node.js 依赖

```powershell
cd d:\learn\trae\tauri_app
npm install
```

## 2. 安装与启动

### 2.1 开发模式

```powershell
cd d:\learn\trae\tauri_app
npm run tauri:dev
```

- 首次启动会编译 Rust 后端（约 5-10 分钟）
- 后续启动约 10-30 秒
- 前端热更新自动生效，Rust 代码修改后自动重新编译

### 2.2 生产构建

```powershell
npm run tauri:build
```

- 输出目录：`src-tauri/target/release/`
- Windows 生成 `.msi` 安装包和 `.exe` 可执行文件
- 安装包路径：`src-tauri/target/release/bundle/msi/`

### 2.3 仅前端开发

```powershell
npm run dev
```

- 仅启动 Vite 开发服务器（无 Tauri 后端）
- 适合纯 UI 开发调试

## 4. 功能模块

### 4.1 首页概览（Dashboard）

- 今日营收、处方数、药材总数、低库存预警
- 近 7 天营收趋势条形图
- 低库存预警列表
- 最近处方列表

### 4.2 药材管理（MedicineList）

- 药材列表（支持分页：每页 10/20/50/100 条）
- 按名称/别名/功效/主治搜索
- 按分类/药性筛选
- 新增/编辑/删除药材
- 查看药材详情卡片
- 导出 CSV

### 4.3 开处方（Prescription）

- 左侧：药材搜索与选择
- 右侧：处方药材列表（可调整数量）
- **配伍禁忌自动预警**（十八反 + 十九畏，共 27 对）
- 保存处方（自动扣减库存）
- 打印处方

### 4.4 库存管理（Inventory）

- 库存列表（含库存状态标识）
- 入库/出库/调整操作
- 按名称搜索、按库存状态筛选
- 设置最低库存预警值
- 导出 CSV

### 4.5 处方历史（History）

- 处方列表（支持分页）
- 按日期范围/患者姓名筛选
- 查看处方明细
- 删除处方（自动恢复库存）
- 打印处方

### 4.6 销售统计（Statistics）

- 5 种时间范围（今日/本周/本月/本季/本年）
- 营收/处方数/药材消耗统计
- 热销药材 TOP 10
- 每日销售趋势

## 5. 批量导入指南

### 5.1 访问路径

- 侧边栏 → 批量导入药材

### 5.2 CSV 文件格式

```csv
name,alias,category,nature,taste,meridian,efficacy,indications,usage,dosage,contraindication,notes,quantity,unit,price,min_stock
人参,棒槌,补虚药,温,甘,脾经,大补元气,体虚欲脱,水煎服,3-9g,实证禁用,,1000,g,120,100
黄芪,黄耆,补虚药,温,甘,脾经,补气升阳,气虚乏力,水煎服,9-30g,,表实邪盛者禁用,800,g,50,100
```

### 5.3 导入步骤

1. 点击「选择文件」上传 CSV 文件
2. 系统自动解析并预览数据
3. 检查预览结果，红色行表示数据有问题
4. 点击「开始导入」
5. 实时查看导入进度和错误日志
6. 导入完成后自动刷新药材列表

### 5.4 导入规则

- **同名药材**：自动更新（UPSERT），不会重复创建
- **必填字段**：`name`（药材名称）
- **数字字段**：`quantity`、`price`、`min_stock` 必须为数字
- **编码格式**：UTF-8（支持 BOM）
- **单引号**：字段值中的单引号会自动处理

### 5.5 下载模板

在批量导入页面点击「下载模板」，获取包含示例数据的 CSV 模板。

## 6. 打印处方

### 6.1 打印方式

- 处方开具页面 → 保存后点击「打印」
- 处方历史页面 → 选择处方 → 点击「打印」

### 6.2 打印内容

打印的处方单包含：
- 药店名称和日期
- 患者信息（姓名/年龄/性别）
- 诊断
- 药材明细表（名称/数量/单位/单价/小计）
- 总金额
- 配伍禁忌提示（如有）

### 6.3 技术实现

使用 iframe `srcdoc` 方案，兼容 Tauri WebView：
- 生成完整 HTML 文档
- 在隐藏 iframe 中加载
- 调用 `window.print()` 触发系统打印对话框
- 所有用户输入经过 HTML 转义，防止 XSS

## 7. 自动更新

### 7.1 配置

在 `Settings` 页面设置更新源：
- **更新源 URL**：Gitee Releases API 地址
- **检查间隔**：默认 24 小时
- **自动检查**：启动时自动检查（可关闭）

### 7.2 更新流程

1. 应用启动 2 秒后自动检查更新（静默）
2. 发现新版本时弹出更新对话框
3. 用户可选择「立即更新」或「跳过此版本」
4. 下载进度实时显示
5. 下载完成后提示安装
6. 安装后自动重启应用

### 7.3 发布更新

1. 在 Gitee 创建新 Release
2. 上传构建产物（`.msi` 或 `.exe`）
3. 更新 `tauri.conf.json` 中的版本号
4. 用户端自动检测到新版本

### 7.4 备份机制

更新前自动创建数据库备份：
- 备份位置：应用数据目录 `/backups/`
- 备份文件名：`medicine_system_backup_YYYYMMDD_HHMMSS.db`
- 自动清理超过 30 天的旧备份

## 8. 数据备份与还原

### 8.1 创建备份

- Settings 页面 → 数据备份 → 「创建备份」
- 备份包含完整数据库快照
- 自动计算 MD5 校验和

### 8.2 还原备份

- Settings 页面 → 备份列表 → 选择备份 → 「还原」
- 还原前自动执行 `PRAGMA wal_checkpoint(FULL)` 确保一致性
- 还原后需要重启应用

### 8.3 备份文件结构

```
backups/
├── manifest.json                              # 备份清单
├── medicine_system_backup_20260721_100000.db  # 数据库文件
├── medicine_system_backup_20260721_100000.md5 # 校验和
└── ...
```

## 9. 开发指南

### 9.1 添加新的 Tauri 命令

**步骤 1：在 `commands.rs` 定义命令**

```rust
#[tauri::command]
pub fn my_command(arg: String, db_state: State<'_, DbState>) -> Result<String, String> {
    let db = db_state.0.lock().map_err(|e| e.to_string())?;
    // 业务逻辑
    Ok("result".to_string())
}
```

**步骤 2：在 `lib.rs` 注册命令**

```rust
.invoke_handler(tauri::generate_handler![
    commands::my_command,
    // ...其他命令
])
```

**步骤 3：前端调用**

```typescript
import { invoke } from '@tauri-apps/api/core';

const result = await invoke<string>('my_command', { arg: 'value' });
```

### 9.2 添加数据库迁移

**步骤 1：创建 SQL 文件**

```
src-tauri/migrations/003_add_new_feature.sql
```

**步骤 2：在 `db.rs` 注册**

```rust
const MIGRATIONS: &[(&str, &str)] = &[
    ("001_init", include_str!("../migrations/001_init.sql")),
    ("002_seed_medicines", include_str!("../migrations/002_seed_medicines.sql")),
    ("003_add_new_feature", include_str!("../migrations/003_add_new_feature.sql")),
];
```

迁移系统会自动执行新迁移，已执行过的会跳过。

## 11. 常见问题

### Q1: `cargo test` 编译失败，提示 MSVC link.exe 缺失

**解决方案：** 切换到 GNU 工具链

```powershell
rustup toolchain install stable-gnu
rustup default stable-gnu
```

### Q2: `npm run tauri:dev` 启动白屏

**可能原因：**
- 前端依赖未安装 → 运行 `npm install`
- Rust 编译未完成 → 等待首次编译完成
- 端口被占用 → 关闭占用 1420 端口的进程

### Q3: 数据库文件位置

**开发模式：** 项目根目录下的 `medicine_system.db`

**生产模式：** 系统应用数据目录
- Windows: `%APPDATA%/com.medicine-system.app/medicine_system.db`

### Q4: 如何重置数据库

删除数据库文件后重启应用，迁移系统会自动重建表结构和种子数据。

### Q5: 批量导入 CSV 编码问题

确保 CSV 文件使用 UTF-8 编码。如果是 Excel 导出的文件，选择「UTF-8」格式保存。

### Q6: 打印处方无响应

确保系统已安装打印机驱动。Tauri 使用系统打印对话框，需要至少一台可用打印机。

### Q7: 自动更新失败

- 检查网络连接
- 确认 Gitee Release 已发布且包含安装包
- 查看 `Settings` 页面的错误提示
- 手动下载安装包覆盖安装

### Q8: 如何修改应用图标

替换 `src-tauri/icons/` 下的图标文件，然后重新构建：

```powershell
npm run tauri:build
```

## 附录：与 Python 版对比

| 特性 | Python 版 | Tauri 版 |
|------|-----------|----------|
| 技术栈 | PySide6 + SQLite | React + Rust + SQLite |
| 安装包大小 | ~80MB（含 Python 运行时） | ~15MB（原生二进制） |
| 启动时间 | ~2 秒 | ~0.5 秒 |
| 内存占用 | ~120MB | ~60MB |
| 数据库 | SQLite（相同 schema） | SQLite（相同 schema） |
| 配伍禁忌 | JSON 规则文件 | Rust 硬编码（性能更高） |
| 缓存 | Python LRU Cache | Rust 原生（按需查询） |
| 自动更新 | 自实现下载器 | Tauri Updater |
| 打印 | QPrinter | iframe srcdoc |
| 跨平台 | Windows/Linux/macOS | Windows/Linux/macOS |

两个版本共享相同的数据库 schema，数据可互通。
